# gover2-parity — Technical Design

## Overview

Brings the gover2 Wails app to feature parity with the PyQt inventory app: startup expiry alerts, CSV export, working dark mode, search, database new/open, About/License, and table density. The existing layout is kept and polished — no redesign, no new asset categories, no schema changes. Most work reuses bridge methods that already exist; the only new Go code is CSV export.

Canonical capability specs live in OpenSpec (`openspec/changes/gover2-parity/specs/`). This document is the technical *how*.

## Architecture

Unchanged dependency chain:

```
models  ←  database
  ↑            ↑
services    (sql.DB)
  ↑
bridge  ←  config, wails/v2/pkg/runtime
  ↑
api/index.ts
  ↑
stores (ui, search) ── Topbar ── AlertsModal ── DataTable ── *View.vue
```

New units are small and single-purpose:
- Go: `services/export.go` (pure CSV building), a thin dialog+write wrapper in `bridge`.
- Frontend: `stores/search.ts`, `lib/filter.ts` (`matchesQuery`), `AboutModal.vue` / `LicenseModal.vue`, a `routeCategory` map.

## Dark Mode — CSS-variable tokens

The Tailwind color tokens are currently static hex, so a root-class toggle alone would not re-theme anything. Convert tokens to CSS custom properties so a single `.dark` class on `<html>` switches the whole palette with no per-component edits.

**`tailwind.config.ts`** — token values become variable references, names unchanged:

```ts
colors: {
  surface: 'var(--c-surface)',
  page:    'var(--c-page)',
  border:  'var(--c-border)',
  'text-primary':   'var(--c-text-primary)',
  'text-secondary': 'var(--c-text-secondary)',
  'th-bg':   'var(--c-th-bg)',
  'th-text': 'var(--c-th-text)',
  // … all themeable tokens; sidebar palette may stay constant (dark in both)
}
```

**`style.css`** — two value sets:

```css
:root {
  --c-surface: #FFFFFF;
  --c-page: #EEF1F7;
  --c-border: #DDE1EC;
  --c-text-primary: #0F172A;
  --c-text-secondary: #64748B;
  --c-th-bg: #0E1520;
  --c-th-text: #8FA5BF;
  /* … */
}
.dark {
  --c-surface: #0E1520;
  --c-page: #0A0F18;
  --c-border: #1E293B;
  --c-text-primary: #DDE8F5;
  --c-text-secondary: #8FA5BF;
  --c-th-bg: #060A12;
  --c-th-text: #6B82A0;
  /* … */
}
```

Intentionally theme-agnostic (left as-is): modal overlays (`bg-black/40`), the red delete button (`bg-red-600`), and status badge colors (semantic across themes).

**`stores/ui.ts`** is the single source of truth. On app start it reads `getConfig()` and sets `darkMode`/`density`; a side effect applies/removes `dark` on `document.documentElement`. `toggleDarkMode()` flips the ref and persists via `setConfig(currentConfig)`. Density setter persists the same way.

## CSV Export — Go-driven

Native dialogs require the Wails runtime and the app context, so export is driven from the bridge rather than the frontend.

**`services/export.go`** (pure, testable):

```go
// BuildCSV returns header + data rows for a category in canonical column order.
func BuildCSV(db *sql.DB, category string) ([][]string, error)

// writeCSV writes rows to path using encoding/csv.
func writeCSV(path string, rows [][]string) error
```

`BuildCSV` switches on `category`, queries via the existing `List*` services (or dedicated SELECTs), and formats each record into the same column order the view shows. Unknown category → error.

**`bridge.ExportCSV`** (signature change from the stub):

```go
func (a *App) ExportCSV(category string) error {
    if a.db == nil { return errNoDB }
    rows, err := services.BuildCSV(a.db, category)
    if err != nil { return err }
    path, err := runtime.SaveFileDialog(a.ctx, runtime.SaveDialogOptions{
        DefaultFilename: category + ".csv",
        Filters: []runtime.FileFilter{{DisplayName: "CSV", Pattern: "*.csv"}},
    })
    if err != nil { return err }
    if path == "" { return nil } // user cancelled
    return services.WriteCSV(path, rows) // exported thin wrapper
}
```

(`writeCSV` is exported as `WriteCSV` so the bridge can call it; or `BuildCSV` returns and bridge writes — either keeps the dialog the only untested line.)

**api**: `exportCSV(category: string): Promise<void>` — drops `destPath`. wailsjs bindings regenerated by `wails build`.

## Search — client-side, store-coordinated

The topbar owns the input but views own their rows, so a tiny store bridges them.

**`stores/search.ts`**: `query` ref + `setQuery`/`clear`. The topbar `v-model`s the input to `query`.

**`lib/filter.ts`**:

```ts
export function matchesQuery(
  row: Record<string, unknown>,
  columns: { key: string }[],
  query: string,
): boolean
```

Empty/whitespace query → always true. Otherwise lower-cases the query and tests whether any column's displayed value (the same `row[col.key] ?? ''` the table renders) contains it.

Each view computes `filteredRows = computed(() => rows.value.filter(r => matchesQuery(r, columns, query.value)))` and passes `filteredRows` to `DataTable`. A `watch(() => route.path, () => searchStore.clear())` (in AppShell or the topbar) prevents query leaking across views.

## Topbar Action Row

`Topbar.vue` becomes the global action host:

```
[ view title ]   🔍 search   ⚠ Alerts   ↓ CSV   🌙 dark   ⋯
                                                          └─ New Database
                                                             Open Database
                                                             ─────────────
                                                             About
                                                             License
```

- A `routeCategory` map (`/computers→computers`, `/windows-keys→windowskeys`, `/antivirus→antivirus`, `/other-software→othersoftware`, `/users→users`, `/smartphones→smartphones`, `/tablets→tablets`) gives the active category for export.
- ↓ CSV is **hidden on `/all`** (aggregate view; Go export is strictly per-category). Search still works on `/all`.
- 🌙 calls `ui.toggleDarkMode()` and reflects state in its icon/label.
- ⋯ overflow: New/Open Database call `newDatabase`/`openDatabase` (native dialogs, Go-side); About/License open local modals. Per-view Add buttons are untouched.

## Alerts at App-Shell Level

`AppShell.vue` owns the modal open-state so it can pop on startup independent of the routed view.

- On mount: `const alerts = await getAlerts(); if (alerts.length) open = true`.
- ⚠ topbar action: re-fetch `getAlerts()` and open (so it reflects current data after edits).
- `AlertsModal.vue` renders a table of `{category, name, expiryDate, daysRemaining, severity}` with severity-colored badges reusing existing status tokens; empty list shows a "no alerts" message; Close emits `close`.

## Density + Zebra

`DataTable.vue` reads `density` from `stores/ui.ts`:
- `comfortable` → `py-2`, `compact` → `py-1` on cells.
- Alternating rows via themed `odd:`/`even:` backgrounds (new `--c-row-alt` token, light + dark).
Both adjust automatically with the theme since they use tokens.

## Error Handling

- Bridge nil-db guard on `ExportCSV` (returns `errNoDB`); api wrappers already `.catch()` to safe defaults for reads.
- Cancelled save dialog → `ExportCSV` returns nil, no file, no error surfaced.
- `BuildCSV` unknown category → error propagated to the frontend (console; toast out of scope).
- DB new/open failures propagate from the existing bridge methods; views refetch after a successful switch.

## Testing Strategy

**Go**
- `BuildCSV`: table-driven per category against in-memory SQLite (`database.Open(":memory:")`) — header + row content + column order; unknown category errors.
- `WriteCSV`: write to a temp file, read back, assert bytes.
- `bridge.ExportCSV`: nil-db guard returns `errNoDB`. The dialog line is left to smoke test.
- Targets: services ≥ 70%, bridge ≥ 50% (existing thresholds).

**Frontend (Vitest + @vue/test-utils)**
- `matchesQuery`: matches across columns, case-insensitive, empty query passes, clear resets.
- `ui` store: toggleDarkMode flips ref + classList; density setter; load-from-config.
- `DataTable`: density prop/store → correct padding class; zebra classes present.
- `AlertsModal`: renders fixture rows; empty list shows empty message; auto-open logic true for non-empty / false for empty.

## Non-Goals

- No visual redesign / new design language.
- No new asset categories, inline cell editing, undo/redo, multi-user/cloud.
- No `AppConfig` schema change.
- No combined-CSV export on `/all` (per-category only in this change).
