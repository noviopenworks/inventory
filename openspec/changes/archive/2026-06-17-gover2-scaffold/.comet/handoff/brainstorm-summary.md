# Brainstorm Summary

- Change: gover2-scaffold
- Date: 2026-06-17

## Confirmed Technical Approach

Execute the locked architecture from `gover-phase1-architecture` exactly. Pure scaffolding — no business logic. All decisions already made in the architecture spec; this change executes them.

**Key implementation-level decisions confirmed:**

1. **wails.json pnpm configuration**: Must set `"frontend:install": "pnpm install"`, `"frontend:build": "pnpm run build"`, `"frontend:dev:watcher": "pnpm run dev"`, `"frontend:dev:serverUrl": "auto"` in `wails.json` before any build. Without this, Wails defaults to npm and the build fails.

2. **Tailwind CSS version**: Pin `tailwindcss@3` explicitly. Tailwind v4 (2025) uses CSS `@theme` directives — incompatible with the locked `tailwind.config.ts` token format. Use `tailwindcss` + `postcss` + `autoprefixer` with the Vite plugin (not `@tailwindcss/vite` which is v4-only).

3. **modernc.org/sqlite blank import**: The `internal/database` stub must include `_ "modernc.org/sqlite"` so the dependency stays in `go.sum` and is not pruned by `go mod tidy`.

4. **TypeScript bindings deferred**: `lib/api/index.ts` in scaffold returns `Promise.resolve([])` directly — it cannot import from `wailsjs/go/bridge/App` yet (those files are generated by `wails build` during gover2-readonly).

5. **Package creation order**: `models` → `database` → `config` → `backup` → `services` → `bridge` (in dependency order).

6. **Bridge struct in app.go**: Wails uses `app.go` as the entry. We update it to instantiate `bridge.NewApp()` and pass it to `wails.Run()` rather than keeping the generated placeholder struct.

## Key Trade-offs and Risks

| Risk | Mitigation |
|---|---|
| Wails defaults to npm | Set wails.json frontend fields before first build |
| Tailwind v4 breaks config | Pin tailwindcss@3 |
| modernc.org/sqlite pruned from go.sum | Blank import `_ "modernc.org/sqlite"` in database stub |
| Import cycle between packages | Create packages in dependency order; verify with `go build ./...` after each group |

## Testing Strategy

Scaffold phase has no business logic — no unit tests for stubs. All verification is build-level:
- `go build ./...` — compilation, no import cycles
- `pnpm run typecheck` (vue-tsc with `"strict": true`) — TypeScript interface correctness
- `wails build` — end-to-end binary production
- `wails dev` (manual) — sidebar shows 7 categories, empty main area, no console errors

No `_test.go` files or Vitest tests needed at scaffold stage. Test infrastructure is added in `gover2-readonly`.
